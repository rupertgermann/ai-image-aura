# OpenAI lineage batch-size history

On 2026-11-09, a new control-snapshot browser scenario exposed a pre-existing distinction at `rupertgermann/ai-image-aura@d823cc31ec67b4a371492ca82fa986d4ae7d5740`: manual OpenAI generation lineage reconstructed controls from per-image archive fields. The [lineage builder](https://github.com/rupertgermann/ai-image-aura/blob/d823cc31ec67b4a371492ca82fa986d4ae7d5740/src/lineage/generateLineageMetadata.ts#L121) used the run draft only for Qwen; [archive-control normalization](https://github.com/rupertgermann/ai-image-aura/blob/d823cc31ec67b4a371492ca82fa986d4ae7d5740/src/image-models/ImageModelControls.ts#L420) supplied no OpenAI batch size, leaving its default of one. Thus a valid three-image HTTP request and generation-session snapshot could coexist with `batchSize: 1` in each saved OpenAI lineage entry.

On 2026-11-09, inspection of the `control-snapshots` JSON attachments in [baseline trace](/tmp/aura-generation-planning/controls-baseline-snapshot/autopilot-failure-Autopilo-bc386-s-and-the-next-manual-batch/trace.zip) and [after-change trace](/tmp/aura-generation-planning/controls-after/autopilot-failure-Autopilo-bc386-s-and-the-next-manual-batch/trace.zip) confirmed HTTP `n: 3`, session `batchSize: 3`, and three lineage entries with `batchSize: 1`, all retaining high quality, `1536x1024` size and transparent background. The baseline was `rupertgermann/ai-image-aura@d7ac16de8f37e6a3fa4796ee5bbaa4997f3c084a`; the control implementation was [`99b305ca7a2a8f11ada55424690477d5020d94de`](https://github.com/rupertgermann/ai-image-aura/commit/99b305ca7a2a8f11ada55424690477d5020d94de).

On 2026-11-09, the coordinator retained that serialization behavior outside [control ticket #181](https://github.com/rupertgermann/ai-image-aura/issues/181), consistent with the persistence-format exclusion in [spec #179](https://github.com/rupertgermann/ai-image-aura/issues/179). The [control report](/tmp/aura-generation-planning/controls-report.md) records the initial expectation correction. This was a documented limitation, not a claim that lineage preserves the original OpenAI request batch size or that the refactor introduced the discrepancy.

On 2026-11-09, final verification at `rupertgermann/ai-image-aura@d5be3c1097aa6510f1864f29bd535bfd46cd6539` retained this limitation outside the approved serialization scope; the [final report](/tmp/aura-generation-planning/integration-verification/final-verification.md) did not claim original request batch size in saved OpenAI lineage.
