# Image Request Mapping

This document maps AURA AI user actions to the provider request payloads generated by the browser client.

## Shared Defaults

All image requests use:

- one selected image model
- one locally stored provider API key
- a single requested output image
- base64 image response handling

Image model mapping:

- `GPT Image 2` in the UI maps to `gpt-image-2` on OpenAI.
- `Nano Banana Pro` in the UI maps to `gemini-3-pro-image-preview` on Google.

Reasoning model mapping:

- `GPT 5.4` in the UI maps to `gpt-5.4` through OpenAI Responses.
- `Gemini 2.5 Flash` in the UI maps to `gemini-2.5-flash` through Google Gemini.

The provider registry lives in `src/utils/openaiModels.ts`. OpenAI request construction lives in `src/utils/openai.ts`; Google image request construction lives in `src/image-workflow/ImageProvider.ts`; reasoning client selection lives in `src/autopilot/ReasoningClient.ts`.

## Generate View Request Mapping

### Shared UI Inputs

The Generate view always collects:

- Image model
- Prompt textarea
- Optional reference images
- Style selector
- Lighting selector
- Palette selector

The app combines the base prompt with selected creative modifiers before sending the image request:

- base prompt
- optional style modifier
- optional lighting modifier
- optional `color palette: ...` modifier

### `gpt-image-2` Prompt-Only Generation

When the selected image model is `gpt-image-2` and the Generate view has no reference images, the app sends a JSON request to the OpenAI generations endpoint.

#### UI Inputs

- Quality: `low`, `medium`, `high`
- Size: `auto`, `1024x1024`, `1536x1024`, `1024x1536`
- Background: `auto`, `opaque`, `transparent`

#### Request Shape

```json
{
  "model": "gpt-image-2",
  "prompt": "<base prompt with optional style, lighting, and palette modifiers>",
  "n": 1,
  "size": "1024x1024 | 1536x1024 | 1024x1536",
  "quality": "low | medium | high",
  "background": "opaque | transparent"
}
```

`size` and `background` are omitted when the UI is set to `auto`.

### `gpt-image-2` Reference-Based Generation

When the selected image model is `gpt-image-2` and the Generate view includes uploaded reference images, the app sends a `FormData` payload to the OpenAI edits endpoint.

#### Request Fields

- `model`
- `prompt`
- `n`
- one `image[]` field per uploaded reference file
- optional `size`
- optional `quality`
- optional `background`

This enables prompt-guided generation using visual references while keeping the same visible Generate controls.

### `nano-banana-pro` Generation

When the selected image model is `nano-banana-pro`, the app sends a Google Gemini `generateContent` request.

#### UI Inputs

- Aspect ratio: `1:1`, `2:3`, `3:2`, `3:4`, `4:3`, `4:5`, `5:4`, `9:16`, `16:9`, `21:9`
- Resolution: `1K`, `2K`, `4K`
- Optional reference images, capped to the first `14` images

#### Request Shape

```json
{
  "contents": [
    {
      "parts": [
        { "text": "<prompt with optional style, lighting, and palette modifiers>" },
        { "inline_data": { "mime_type": "image/png", "data": "<base64 reference>" } }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1 | 2:3 | 3:2 | 3:4 | 4:3 | 4:5 | 5:4 | 9:16 | 16:9 | 21:9",
      "imageSize": "1K | 2K | 4K"
    }
  }
}
```

The Google provider uses the same endpoint for prompt-only and reference-guided generation. Reference images are sent as additional inline image parts after the prompt text.

## Editor View Request Mapping

The Editor view always starts from the current layered composition.

### AI Transform Targeting

When the user runs an AI transform:

- selected visible non-base layers are flattened into a bounded target image when such a selection exists
- the whole visible composition is used as the edit target when no editable layer is selected
- the whole visible composition is sent as context when selected layers are targeted
- user-supplied visual context references are appended after the target and composition context

The selected image model controls the provider request. The Editor model defaults to the archived image model when possible, and the user can switch models before running the transform.

### `gpt-image-2` Editor Transform

OpenAI editor transforms send a `FormData` payload to `POST /v1/images/edits`.

#### Request Fields

- `model`
- `prompt`
- `n`
- `image[]` entries for the edit target, optional composition context, and optional references
- `quality: medium`

Editor transforms do not expose OpenAI size or background controls.

### `nano-banana-pro` Editor Transform

Google editor transforms send a Gemini `generateContent` request containing:

- prompt text
- inline image part for the edit target
- optional inline image part for composition context
- optional inline image parts for user references
- `generationConfig.responseModalities: ["IMAGE"]`

Editor transforms preserve the source composition dimensions by omitting `imageConfig.aspectRatio` and `imageConfig.imageSize`.

### AI Result Handling

After a successful AI transform:

- the returned image becomes a new `AI result` layer
- the AI result layer is inserted directly above the topmost targeted layer
- targeted non-base layers are hidden by default
- the base layer remains visible if it is part of the target set
- the editor draft is marked dirty and can be saved, reverted, undone, or redone

### Save Flows After an Edit

After an edited composition exists locally:

- `Save Changes` overwrites the current archive image
- `Save as Copy` creates a new archive image
- flattened image output is saved for browsing and downloads
- durable layer stack metadata and layer assets are saved for layered images
- lineage metadata is written locally based on the action and edit context

These save paths do not issue additional provider requests.

## Autopilot Request Mapping

Autopilot combines image and reasoning calls into a loop.

### Goal Translation

The `Translate to Prompt` action sends a reasoning request with:

- the selected reasoning model
- a system prompt that asks for one concise image-generation prompt
- user text in the form `Creative goal:\n...`

The returned text replaces the current Generate prompt.

### Iteration Loop

Each Autopilot iteration performs:

1. An image request using the selected image model, current Generate settings, and active reference images
2. A reasoning evaluation request that includes:
   - the creative goal as text
   - the generated image as provider-specific image input
3. A reasoning refinement request that includes:
   - the creative goal
   - the current prompt
   - evaluator feedback as bullet-style text

The refinement step is skipped after the final iteration or when the satisfaction threshold is met.

### Iteration Metadata

For each completed iteration, the app records local lineage metadata containing:

- `goalText`
- `iterationNumber`
- `evaluatorScore`
- `evaluatorFeedback`
- the prompt and generation settings used for that iteration
- `outputImageDataUrl` for replay and timeline preview

## Response Handling

OpenAI image requests return:

```json
{
  "data": [
    {
      "b64_json": "..."
    }
  ]
}
```

Google image requests return image data inside candidate parts:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "inlineData": {
              "data": "..."
            }
          }
        ]
      }
    }
  ]
}
```

OpenAI Responses requests accept either:

- a top-level `output_text` field
- `output[].content[]` entries with `type: "output_text"`

Google reasoning requests read text from `candidates[].content.parts[].text`.

Image payloads are converted into browser data URLs and then:

- previewed in the current view
- saved locally when the user archives the image
- reused in archive detail and editor flows as needed

Reasoning text is trimmed and then used as:

- a translated prompt
- parsed evaluation JSON
- a refined prompt

## Current Limitations

- GPT Image 2 Generate runs may request a batch of 1-4 images with the native
  `n` parameter; edit operations and Autopilot iterations request one image.
- The app does not use streaming responses.
- The app requests Editor transform masks for `gpt-image-2` only; it does not
  request variations.
- The app does not expose output format or compression controls.
- OpenAI editor transforms always use `quality: medium`.
- `nano-banana-pro` uses at most the first `14` reference images.
